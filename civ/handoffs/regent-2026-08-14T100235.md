## What the sitting found that the brief did not say

1. **Acceptance criterion 2's literal wording would have destroyed something.**
   `grep -rn '{{'` over a founded tree cannot return nothing: every seat file
   deliberately carries `{{UNFILLED — set at the Founding Moot}}` and the
   personality marker saying a fort must never inherit another settlement's
   citizen. Emptying that grep means deleting exactly what SO12 protects. The
   check taken is the render-token shape `{{[A-Z_]*}}`.
2. **Two template comments carried a brace literal**, and `mayor.sh`'s copy was
   already shipping into every founded fort. Reworded so the check above can be
   zero-tolerance rather than an exception list.
3. **`fortkit-ugw4`'s "two lines, not one" precision is backwards.** `mask_env`
   appends `--clearenv`, so a host-side `export` cannot reach the session;
   `--setenv` is the whole mechanism and `mayor.sh:54`'s own export is dead code
   beside it. Measured: `FOO=hostval bwrap … --clearenv --setenv BAR 1 -- env`
   prints `BAR` and not `FOO`. One line went into each launcher — which is also
   exactly what Farlantern has shipped in production since `longburn-5v4`.
4. **`fortkit-0po6`'s premise about `fortkit-4wlz` is wrong in both directions.**
   4wlz is OPEN, carried by `fortkit-52vf.7`; it records no "no absolute-path
   denies" decision, only a recommendation about two `.ssh`/`.aws` lines; and its
   own option (b) *is* the `{{HOME}}` placeholder the Overseer has now ruled in.
   Recorded on both beads, and criterion 6's narrowing recorded with it.

## What failed

- **The marker harness died silently on its first outing** against
  `longburn/fort/scripts/forge.sh` — the extracted block reads `$bead`, `set -u`
  is fatal to the whole shell and not just the `eval`, and the run printed
  **nothing at all**: five of six lines where six were expected. A harness that
  can vanish is a harness that can score a defect as a pass. Fixed by relaxing
  `-u` across the `eval` only, and the empty-extraction refusal plus the explicit
  PASS/FAIL line are what make a silent death visible. It was found by counting
  the output lines, not by any check.
- **My first `status.sh` draft kept `[ "$AHEAD" -gt 3 ] && echo` as the last
  command of a branch**, which makes a false threshold the block's exit status —
  a scar `seat-sandbox.sh:525` already carries a comment about. Caught by the
  harness returning exit 1 on a healthy repository; rewritten as an `if`.
- **Three commands were refused by the harness even to this unmasked seat**, and
  each cost a round trip: `rm -rf` on a scratch directory (known), and `cp` with
  `fort/scripts/…` on *either* side — the deny extends to the source, not only
  the destination. `python3 shutil.copyfile` is the lane.
- **The `bd comment … --file -` heredoc form is ambiguous** and I could not tell
  from the output which branch of my `||` had run. The comment that landed was
  the right one, checked with `bd show`. Use a real file.

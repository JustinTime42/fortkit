## What failed, or went wrong

- **My first harness scored a masked file as FAIL.** `wc -c < file 2>/dev/null ||
  echo UNREADABLE` with stderr merged turned an EACCES read into
  `bash: ...Permission denied UNREADABLE`, which matched neither branch. A probe
  that cannot tell "masked" from "readable" is the same class of error as the
  thing it is probing. Caught on the positive control, fixed to
  `cat 2>/dev/null | wc -c`, which is always numeric.
- **My first patcher did not reproduce the file I had proven.** Three comment
  hunks differed. I fixed the patcher rather than the output, so all four
  installed files come from one reviewed generator and the harness-proven file is
  one of them.
- **A backtick in a `bd comment` was command-substituted**, deleting one word
  from a bead comment and printing `bash: script: command not found`. Correction
  appended to `fortkit-52vf.3`, not edited in. Cost one word this time; the same
  construction with a different word inside the backticks would have *run* it.
- **My first `kill -0` liveness check reported all three smokes dead** when all
  three were running — I parsed `"fortkit warden smoke pid=NNN"` with
  `read -r n p` and got `p=warden`. Nearly re-launched three sessions on top of
  three live ones.
- **The interactive Mayor cannot be launched headless.** `claude` with stdin from
  `/dev/null` exits immediately, and util-linux `script` is **not installed on
  this host**. `python3 -c "import pty; pty.spawn([...])"` is what made a real
  `mayor.sh` launch possible.

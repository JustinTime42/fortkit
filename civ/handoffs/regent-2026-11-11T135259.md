## What failed, and the lessons

- **My first Docker verify was RED** at forge-refresh-harness nz3u: a case
  pinned the Forge prompt's last line, and part B appended a section. Fixed by
  asserting the property (43fa7560d). The verifier is fail-fast, so every step
  after it was unmeasured until the re-run.
- **Belt 2 as I first built it did not do what the charter text said** (Tova
  round two): it listed only sign-to-land beads, but the ESCALATE route adds
  `human` and never sign-to-land, so the ordinary held sitting was invisible; my
  e2e fixture HAND-WROTE a label set the fleet never produces and so hid it; and
  a single `git merge-base` misses shared commits in the criss-cross every pair
  of sittings reaches after both merge main. A fixture that writes the state the
  code is supposed to react to, instead of producing it through the real route,
  tests the code against a world that does not occur.
- **A harness stub that ignores a filter the caller relies on makes the red arm
  fail for the wrong reason** (F3 first red showed "found T-n1" instead of
  "missed T-h1"); the stub now honours --label.
- **Instrument defects presenting as subject defects, again**: a stub function
  using `$3` meant its own third argument; a stub log split across physical
  lines defeated a `grep '^create' | grep label`; a missing-function case
  passed vacuously against the old file (D1b, B14) until each asserted the
  function exists.
- **A mini-runner I extracted from the e2e harness broke silently** (printed
  nothing); I abandoned it for two full sequential runs rather than debug it.

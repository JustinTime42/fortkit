## What each one actually changed

**`a2fx` — a stopped run records that it was stopped.** INT/TERM traps set the
reason before the EXIT trap and the distinction reaches the PAYLOAD
(`interrupted`, `signal`). The stop is a DRAIN: three places that read a child's
exit status now ask `signalled()` first, because Ctrl-C reaches the whole
foreground process group and the verifier or review it kills reports nonzero for
a reason that has nothing to do with the bead. The mid-run HALT check exists
now: the file was read at preflight and by nothing else, so the obvious operator
reflex did nothing to a running fleet. `report_leftovers()` names what the run
walks away from, on every exit path.

**`w7u5` — one lifecycle owner, and it names its case.** `done` meant both "the
Forge ended" and "nothing further will happen here"; all five sightings are that
conflation. Nothing writes `done` any more. States live in `$wdir/state` as
`token|run-id|reason`, and the four cases of the taxonomy are distinguishable:
`parked-budget` and `parked-review` are healthy and self-resuming,
`deferred-merge` is healthy, `orphaned` and `needs-person` need a person.
`worker_resume_at()` is the half that matters — a worker parked before its
review resumes AT the review.

**`usz6` — the deferred merge is retried, and the retry is the merge alone.**
Three near-identical defer branches become one `defer_merge()` that persists the
verdict and a COPY of the Warden record before the first thing that can defer.
Four fail-closed checks on the retry. The budget does not gate it (a merge
spends no launch). One `fleet.deferred` per distinct reason, not per pass.

**`dx34.3` — the dispatcher survives its terminal.** `trap '' HUP`, and the
narrative goes to `$FLEET_STATE/logs/run-<id>.log` FIRST and the terminal
second, because once the terminal is gone a stdout write returns EIO and an
unguarded `printf` in `say()` would end the run under `set -e`.

## What failed, and what I got wrong

1. **My first live probe measured nothing, and the reason is now a recorded
   operational fact.** I launched fleet.sh as a background job and sent
   `kill -INT`: the run kept dispatching for two minutes. **bash ignores SIGINT
   for asynchronous commands, and a signal ignored on entry cannot be trapped**,
   so the trap I was testing was a no-op in that posture. Three controls settle
   it: Ctrl-C on a pty traps and exits 130; `kill -INT` on a background job does
   nothing; `kill -TERM` works everywhere. Written into the head of fleet.sh,
   because the next operator's reflex would otherwise fail in silence — the same
   shape as the halt file `a2fx` was filed about. It also decides the stop
   mechanism for `dx34.3`'s detached posture.
2. **I quoted the retired `touch "$d/done"` call in the comment explaining its
   removal**, so the zero-tolerance harness case scored the fix at one site and
   failed. Fourth sighting of this class in this civilization. Paraphrased.
3. **`--status` would have died on an unbound variable.** It deliberately runs
   before preflight, and the lifecycle owner reads `FLEET_LAUNCH_GRACE`. Caught
   by running `--status`, not by reading. Fixed before install.
4. **Two defects in my own harness, either of which could have been read as a
   defect in the fix**: the git fixture merged the wrong branch into main, so
   "a deferred merge is retried" was measuring the already-merged case; and the
   shared `harness()` stubs `emit` to a no-op, so the case about what reaches the
   stream scored zero emits.
5. **`worker_resume_at` is multi-line**, and I put it in the harness's one-liner
   `grep` list, which truncated the extraction mid-function and made five cases
   report a bash syntax error rather than a result.
6. **`grep -E` has no `\n`**, so my first multi-line assertions matched nothing
   and warned "stray \ before n" on stderr — a broken assertion that reads like
   a failing one. Replaced with per-string `grep -F`.

## Two measured corrections to the beads' own text, appended not edited

- **`a2fx` fact 2 is narrower than it reads.** It says an interrupted run's
  detached Forge is reaped by NOBODY. `reap_pass` iterates every worker
  directory, not this run's, and takes any with `exit` and without `done` — so
  **the next run reaps it**. The true claim is "nobody reaps it in THIS run",
  and that is why the fix is the leftovers report rather than a kill: what was
  wrong was that the wait was silent.
- **`kill -INT` does nothing to a detached run** (item 1 above).

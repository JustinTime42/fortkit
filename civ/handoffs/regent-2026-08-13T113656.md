   divergent" is NOT met, and I argue it should not be.** With identity fully
   erased the capital's `mayor.sh` still carries one genuine architecture hunk:

   `templates/fort/scripts/mayor.sh`, which changes what two other settlements
   are offered. **That is Band 3 and I deliberately did not take it. It is the
   Overseer's call and it is flagged on `fortkit-52vf.11`.**

   says "if the new run still reports defer 0 while those paths are absent, the
   fix did not work." Defer is still 0 and the fix works: every one of the nine
   absent paths already has a bead, so none reaches the defer branch — the
   branch is unreachable in the live civilization, which is why the BASELINE
   read 0 rather than 9. The number that moved is `propagationGaps` 0 → 9.
   Recorded on the bead rather than quietly reinterpreted.
3. **I ran the positive control second, not first.** The fort's own rule is
   "run the harness against the old file FIRST." I built, installed, and passed
   20/20, and only then reverted to the pre-image to score the new tests against
   it. The result was clean (6/6, exactly the targeted defects) so nothing is
   in doubt — but had it come back 0 failures I would have discovered that after
   committing myself to the design rather than before. The discipline exists for
   the ordering, not the arithmetic.
4. **The live three-fort roster assertion is NOT a committed test.** The bead
   asks for it asserted by output; a test reading `/home/justin/dev/longburn`
   would fail in any other checkout, so the suite pins the two spellings against
   verbatim fixtures and the live assertion is recorded as command output here
   and on `fortkit-9qts`. A deliberate split, not an omission.

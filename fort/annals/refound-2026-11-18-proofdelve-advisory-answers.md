# Advisories — Proofdelve's answers

What this file is, in one line: **the record of what this fort did about defects
found somewhere else in the civilization.**

Advisories are published in `fortkit/civ/advisories/`. They are service
bulletins, never instructions (charter standing order 17 — Manyhalls numbers the
same order 13, so cite it by name). What this fort owes an advisory is an
**answer**, not compliance. "Present, and we are not fixing it, because our
design makes it moot" is a complete and good answer. The only failure state is a
row that is never filled in, because an unanswered advisory is indistinguishable
from one nobody saw.

## How to fill a row

- **Checked** — the date someone actually ran it here. Not the date it was published.
- **Result** — one of:
  - `PRESENT` — this fort has the named flaw.
  - `NOT PRESENT` — checked, and this fort does not have it. Only claim this
    where the implementation is genuinely shared.
  - `NOT APPLICABLE` — this fort built its own version, or has no such component.
    **This is not an all-clear.** A check that finds nothing in a fort that built
    its own thing has established nothing, and recording it as clean is the one
    error this table is designed to prevent.
  - `UNRESOLVED` — checked, and the advisory's own claim is not yet settled.
- **Decision** — what this fort decided, in this fort's words. Declining is
  first-class and needs no apology, only a reason.
- **Bead** — where the work or the reasoning lives. `—` if the decision was to
  do nothing and the row itself is the whole record.
